한 줄 요약: 무엇이 어떻게 깨졌고 원인은 무엇이었나.

# 1. 증상

관측된 것만 쓴다. 추측은 아직 넣지 않는다. 에러 메시지·로그는 그대로 붙인다.

```
에러 로그 원문
```

# 2. 재현

최소 재현 절차. 어떤 조건에서 나고 어떤 조건에서 안 나는지.

| 조건 | 결과 |
|---|---|
| 로컬 | 정상 |
| CI | 실패 |

# 3. 세운 가설과 기각

여기가 이 글의 핵심이다. 틀린 가설도 **왜 틀렸는지와 함께** 남긴다 —
같은 함정에 빠질 사람에게 가장 쓸모 있는 부분이다.

- **가설 A**: … → 기각. 근거:
- **가설 B**: … → 기각. 근거:
- **가설 C**: … → 적중.

# 4. 원인

진짜 원인. 왜 그렇게 동작하는지 근거(문서·소스·이슈 링크)까지.

# 5. 수정

```diff
- 고치기 전
+ 고친 후
```

# 6. 배운 것

다음에 같은 증상을 보면 어디부터 볼 것인가. 한두 줄이면 충분하다.
